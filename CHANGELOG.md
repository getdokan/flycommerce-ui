# Changelog

All notable changes to `@flycommerce/ui` are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [semantic versioning](https://semver.org).

## [Unreleased]

### Added

- `PeriodMenu`: a toolbar date filter, `<PeriodMenu label presets allLabel value onValueChange range onRangeChange maxDate />`. One outline button with a calendar icon that reads the period ("This month", "All time", or the custom span "Sep 1 – Sep 30", with the year when it isn't this year), opening the presets as radio items, then "All time" when `allLabel` is set, then "Custom range…" when `onRangeChange` is set, itself a radio item that is ticked while a custom range is in force. Custom range opens a two-month calendar (one on phones) anchored to the button, with days after `maxDate` or before `minDate` unavailable, the picked span under it, and Cancel and Apply; one day applies as a one-day range. The range is whole local days with `to` included. Focus returns to the button, unless the user clicked or tabbed elsewhere. `value` is a preset's value, `"all"` (`PERIOD_ALL_TIME`) or `"custom"` (`PERIOD_CUSTOM_RANGE`). `locale` writes the span in the locale's own order ("1. Sept." in German) and translates the calendar, `formatRange` replaces the span's format, and every string is in `labels`.

## [0.5.0] - 2026-10-23

New: `EmptyState` (a one-line empty or failed list), translatable built-in labels and a `locale` for dates, numbers and file sizes across sheets, sidebar, date pickers, the media picker and table filters, person colours for avatars without a picture, and right-to-left fixes.

**Check when upgrading (right-to-left apps):**

- Directional icons now mirror in RTL by themselves: `back`, `forward`, `prev`, `next`, `redirects`, `impersonate`, `signOut`, `sidebarToggle` and `list`. Remove any flip your app adds to these (`rtl:-scale-x-100`, `rtl:rotate-180`, or a flipped wrapper), or they turn back to their LTR direction. Pass `mirror={false}` to keep one as drawn.
- An LTR block inside an RTL page (a code sample, an English address) still mirrors these icons, because the RTL rule follows the page; pass `mirror={false}` there.
- Drop per-item tooltip sides on a right-hand `Sidebar`: its tooltips now open toward the page by themselves.
- Apps that already pass `locale` to `UploadQueue` or `MediaPickerDialog` now see the upload percent in that locale ("%62" in Turkish).

Left-to-right layouts look the same as before.

### Added

- `EmptyState`: an empty or failed list in one line, `<EmptyState icon={<Icon name="products" />} title description actions />`, built from the `Empty` parts. `tone="destructive"` tints the icon tile red for a list that failed to load, `media` shows an illustration without the tile, and a missing `description` or `actions` (including `false` from `cond && …`) leaves its row out. The icon is an element, so `EmptyState` adds no icons to an app's bundle beyond the one it passes. `DataTable` is unchanged.
- `EmptyMedia tone="destructive"` (with `variant="icon"`): the red tile on its own, for apps that compose the `Empty` parts.
- Translatable built-in labels. Each one is a prop whose default is the English text shown today, so nothing changes until an app passes a translation:
  - `SheetContent closeLabel` (default "Close") names the close button, like `DialogContent closeLabel`. `DialogFooter closeLabel` (default "Close") is the text of the button `showCloseButton` adds, and `CommandDialog closeLabel` names its dialog's close button.
  - `Sidebar labels`: `title` (default "Sidebar") and `description` (default "Displays the mobile sidebar.") name the mobile sheet for screen readers; the `SidebarLabels` type is exported. `SidebarTrigger label` (default "Toggle Sidebar") names the trigger.
  - `BreadcrumbEllipsis label` (default "More"), like `PaginationEllipsis label`; `CarouselPrevious label` and `CarouselNext label` (default "Previous slide" and "Next slide"); `MessageScrollerButton label` (default "Scroll to end", or "Scroll to start" with `direction="start"`).
  - `DateRangePicker presetsLabel` (default "Presets") names the preset list.
  - `MediaPickerDialog` labels: `close` (default "Close"), `dropInput`, the drop zone's file input (default "Upload files"), `clearSearch` (default "Clear search") and `queue`, the `UploadQueue` labels of its upload rows ("Uploading…", "Complete", "Failed", "{loaded} of {total}", "Cancel {name}" and "Remove {name}").
  - `ImageUploadField labels.fileRules(types, maxSize)` words the drop zone's description from the accepted types ("PNG, JPG, SVG or WebP") and the size limit ("5 MB"), either of which can be missing. The default still gives "PNG, JPG, SVG or WebP. Max file size: 5 MB"; `labels.description` still replaces it outright.
  - `DataTable` labels: `row(index)` names a row in the reorder announcements when `getRowLabel` isn't set (default "Row 1", "Row 2"…). `dragHandleRole` (default "sortable") and `dragInstructions` (default dnd-kit's "To pick up a draggable item, press the space bar. …") are the role and the keyboard instructions screen readers read on a drag handle, which came from dnd-kit in English only. `OptionListEditor` takes the same `dragHandleRole` and `dragInstructions`.
- `locale` for dates, numbers and file sizes, formatted through `Intl` or date-fns instead of in English:
  - `DatePicker locale` and `DateRangePicker locale` format the trigger's dates and the calendar. Pass a date-fns locale (`import { tr } from "date-fns/locale"`), or one from `react-day-picker/locale`, which also translates the calendar's buttons ("Go to the Previous Month"). The default `displayFormat` is now date-fns's localized medium date, "PP" ("PPp" with `withTime`), which renders the same "Oct 20, 2026" ("Oct 20, 2026, 9:00 AM") in English as the old "MMM d, yyyy" pattern, and "20 Eki 2026" with `locale={tr}`.
  - `ImageUploadField locale` formats the image's size, the size limit and the list of accepted types: `locale="tr"` gives "1,5 MB" and "PNG, JPG, SVG veya WebP".
  - `TableFilters` and `ActiveFilters` labels: `close` (default "Close") names the sheet's close button, `dateRangePlaceholder` ("Pick a date range") and `datePresets` ("Presets") go to the date-range fields, `selected(count)` ("3 selected") and `on` ("On") word the chips. `TableFilters locale` and `datePresets` pass through to its date-range fields, and `ActiveFilters locale` formats date-range chips in the locale's own order ("20 Eki – 25 Eki" with `tr`); without it they stay "Oct 20 – Oct 25".
  - `UploadQueue locale`, and so `MediaPickerDialog locale`, also formats the percent: "%62" in Turkish. Without a locale it stays "62%".
- `AvatarFallback colorFrom`: a person without a picture takes one of eight person colours, always the same for the same key, with white initials. Pass the person's id (a string or a number; the email only for a guest with no id), the same on every screen. Without a key, or with an empty one, the fallback stays grey. The colours are new `--person-1` to `--person-8` tokens (`bg-person-*`), for people only: muted and deep, with white text at 5.6:1 or more on each. In dark mode person-4, -5 and -6 are lighter so every circle keeps 2.5:1 or more against the dark card.
- `Avatar size="xl"` (48px) and `size="2xl"` (64px), for profile and detail headers, with initials and `AvatarBadge` scaled to match.

### Fixed

- `Icon` mirrors the directional names in right-to-left layouts, which changes the default there: `back`, `forward`, `prev`, `next`, `redirects`, `impersonate`, `signOut`, `sidebarToggle` and `list` flip horizontally under `<DirectionProvider dir="rtl">` or inside an element with `dir="rtl"`, server-rendered markup included. No other name mirrors (clocks, checkmarks, `external`, `refresh`, media and brand glyphs keep their direction), and left-to-right layouts look exactly as before. If your app already flips one of these icons, remove the flip: `rtl:-scale-x-100` on the icon itself is harmless, since it still mirrors once, but `rtl:rotate-180` on it, or a wrapper that flips it, now turns it back. To keep an icon as drawn, for example a chevron you rotate yourself, pass `mirror={false}`. `MIRRORED_ICONS` lists the names, and a mirroring icon carries `data-mirror`.
- `SidebarMenuButton` tooltips open on the side away from the rail: to the right of a left rail, as before, and to the left of `Sidebar side="right"`, the rail of an RTL layout, where they opened over the page edge. A `side` in `tooltip={{ side }}` still wins.
- In RTL, edges keyed to a physical side stay on that side. The `Sidebar` rail and `SheetContent side="left"` or `"right"` drew their border on the screen edge instead of the edge facing the page, and `Drawer direction="left"` or `"right"` was pinned to the opposite edge from the one it slides in from. `SidebarRail` showed resize cursors pointing the wrong way, and on a hidden off-canvas right rail its handle sat off screen. `SelectContent side="left"` or `"right"` moved its 4px gap toward the trigger.
- `Carousel` follows `DirectionProvider`: in RTL, Next scrolled into empty space because Embla wasn't told the direction, the arrow keys went the wrong way, and a vertical carousel's buttons pointed down and up. `opts.direction` still wins.
- `Calendar` follows `DirectionProvider`: in RTL, the left and right arrow keys moved focus to the day on the other side. Without a provider it still inherits the page's `dir`.
- `DirectionProvider` sets the direction of the Base UI parts too. In RTL, the arrow keys moved focus between a `Combobox`'s chips and its input the wrong way: Left jumped to the chip drawn to the input's right.
- `TableFilters` opens its sheet at the end edge: on the left in RTL, and on the right as before.

## [0.4.0] - 2026-10-20

New: `Text` and the P3 type scale, `P3IconProvider` and the P3 icon set, `CodeEditor` (opt-in entry), `Timeline` and `ActivityFeed`, `CopyField`, `ColorInput`, `ImageUploadField`, pill buttons, `BrandMark` and `CardBrandMark`, settings field patterns (`FieldCount`, `SwitchField variant="row"`, option rows, `CheckboxCard`, saved secrets), a light sidebar, and AI rewrite actions in `RichTextEditor`.

**Check when upgrading:**

- **Breaking:** install `sonner@^2` alongside the library. It is a peer dependency now; Yarn doesn't add it for you.
- Every `Select` opens below its field instead of over it, and highlighted rows in menus, selects and comboboxes take a soft brand tint (see Changed).
- `SaveBar` looks like the dashboard's unsaved-changes bar: a wide `gray-900` bar with white text, an outlined Discard and "Save changes".
- `Icon` and `Input` are client components (`"use client"`).
- `RichTextEditor` no longer calls `onChange` on mount, when `disabled` changes or around Generate; an app that marked its form dirty from that first call stops doing so.

**Visual changes:**

- Sidebar colours: the rail takes the dashboard design's P3 colours, so text is slightly dimmer, lines slightly brighter and group headings reach 4.5:1, and its edge line is the rail's own dark border instead of the page border.
- Tooltip and toast colours: `#09090b` in both page themes, was `#0a0a10` (`#05050a` on a dark page).
- Cmd/Ctrl+B no longer toggles the sidebar while focus is in a field.

### Added

- `ComboboxChip` `removeLabel` (default "Remove") names the chip's remove button, which had no accessible name. Pass a translation, or a label per chip such as `` `Remove ${value}` ``.
- `CopyField`: a read-only value with an icon-only copy button at its end, for callback URLs, DNS records, keys and codes. `mono` sets monospace text; `label` adds a visible label (or pass `id` and use your own `Field` and `FieldLabel`); `copyLabel` names the button, by default "Copy {label}" when `label` is text (`label="API key"` gives "Copy API key") and "Copy" otherwise, and `copiedLabel` (default "Copied") names it after copying, announced to screen readers; `onCopy` fires after a copy; `disabled` disables the field and the button. Long values end in an ellipsis, and URLs and codes keep their own reading direction in RTL.
- `ColorInput`: a hex colour field, with a swatch over the native colour picker and a `#` text field. It takes 3 or 6 hex digits, typed or pasted with or without a `#` (`#1F2A44`, `1f2a44` and `#ABC` all work), and passes `onValueChange` lower-case `#rrggbb` (`#ABC` becomes `#aabbcc`), or `null` when empty. Any other text is invalid and comes through after a `#` without being read as a colour: `rgb(255,0,0)` and colour names aren't converted, and alpha isn't supported, so 4- and 8-digit hex is invalid too. While the text isn't a colour, or when `invalid` is set, it marks itself invalid (`aria-invalid`, `data-invalid` and an empty swatch); like other inputs, it leaves the message to its field: check the value against `/^#[0-9a-f]{6}$/` and render `Field data-invalid` with a `FieldError`. `allowClear` makes an empty field valid and shows a clear button while there is a value (`labels.clear`, e.g. "Use brand colour"); `fallback` is the colour the swatch and picker show while the field is empty, e.g. the inherited brand colour. Also `disabled` and `labels` (`picker`, `clear`). Use it inside `Field` with `FieldLabel htmlFor`.
- `ImageUploadField`: one image with a preview. Empty, it's a `Dropzone` with "Drag and drop your image here", the accepted types read from `accept` (`image/png` gives "PNG") and the size limit, "Upload image", and "Media library" when `onChooseExisting` is set (open `MediaPickerDialog` from it). Filled, it shows the image on a 96×64 tile, cropped to fill it (`previewFit="contain"` fits it inside instead), its name and size, a remove button (`onRemove`), "Change image", which opens the file picker and applies the same `accept` and `maxSize` checks, and "Media library". `label`, such as "Logo", is added to each button's accessible name ("Change image, Logo"), so several fields on a page stay distinct while the visible text stays the same; `id` and `aria-describedby` go to the file input, for `FieldLabel htmlFor` and a `FieldError`. `preview` draws a node in the tile instead of the image, such as a wordmark drawn in markup, and `value.src` can then be left out. `previewBackground` colours the tile, e.g. the brand colour behind a logo; its text is white, or dark when a hex colour is light. Both states are 148px tall. Also `onFiles`, `onReject` (the `Dropzone` rejection type), `accept` (default PNG, JPG, SVG and WebP), `maxSize`, `loading` (dims the field under a spinner and announces "Uploading"), `invalid`, `disabled` and `labels`. Keyboard focus stays in the field when it switches between empty and filled.
- `Dropzone` `icon`: replaces the upload icon; `icon={null}` leaves it out.
- `on-dark` and `on-light` colour tokens (`text-on-dark`, `text-on-light`): white and dark ink for text on a custom colour, such as a logo on the brand colour, the same in both themes.
- `Button shape="pill"`: the pill call to action. At the default size it is 44px tall and fully rounded, presses in slightly (98%) and eases its colours over 200ms on the new `ease-fluid` curve; at other sizes it is only rounded, e.g. `size="sm" shape="pill"` for a small action in a notice row. The button gets `data-shape="pill"`. Buttons without `shape` look as before.
- `ButtonArrow`: the forward arrow of a pill, in its own 32px circle at the end, tinted for the button (white at 15% on a primary or solid button, `muted` on the others), sliding 2px on hover and flipped in RTL. `pinned` makes a full-width pill whose label centres across it, with the arrow held at the end.
- `BrandMark`: a third-party logo (gateway, carrier, app) on a white tile that stays white in dark mode, because logos are drawn for white. Sizes `xs` to `2xl` (20 to 80px) with corners a quarter of the size, a hairline ring and a soft shadow; 8px padding, which a padding class can tighten for a given logo; `fill` for an app icon that reaches the edges. Takes `src` or an SVG child, and is decorative unless `label` names it. `color` sets the glyph's colour and `background` the tile's, so a brand's own colours come in as data rather than as classes or `style`.
- `Tray`: the double-bezel lead, a tinted tray (18px corners, 6px bezel) holding a white plate. The `primary` tone (default) is blue with a blue-tinted plate shadow, `neutral` is grey, and `warning` and `destructive` make the warning notice, with a neutral plate shadow. `header` sits on the tray above the plate; `className` styles the tray and `contentClassName` the plate.
- `CardBrandMark`: full-colour Visa, Mastercard, American Express, UnionPay, Discover, JCB and Diners Club cards, `size` tall (24 by default) and 1.56 times as wide, with 4px corners and a hairline ring. It takes the brand strings `CardBrandIcon` takes, and unknown brands show the generic card in the same space. The size is also set inline, so a parent that sizes every SVG inside it, such as `ItemMedia`, can't shrink it. The marks are the "flat-rounded" set of aaronfagan/svg-credit-card-payment-icons (Apache-2.0), bundled as React components, with the licence in the new `THIRD_PARTY_NOTICES.md`. They live in their own component so that apps using only `CardBrandIcon` don't bundle them.
- Tokens for these: `--brand-mark`, `--brand-mark-ring`, `--brand-mark-radius`, `--elevation-brand-mark`, `--card-brand-ring`, `--tray-radius`, `--elevation-lead`, `--elevation-notice` and `--motion-fluid`, as the utilities `bg-brand-mark`, `ring-brand-mark-ring`, `rounded-brand-mark`, `shadow-brand-mark`, `ring-card-brand-ring`, `rounded-tray`, `shadow-lead`, `shadow-notice` and `ease-fluid`. In dark mode the brand mark and card mark rings are white at 10% so they stay visible, the lead glow is half as strong, and the notice shadow is black like the other dark elevations.
- Claude plugin: the "which component" table covers pill calls to action, brand marks, the lead tray and colour card marks. A brand's own `react-icons/si` logo inside `BrandMark` is the one exception to importing `react-icons`: the app adds `react-icons` to its own `package.json` and passes the brand's colours to `color` and `background`; otherwise it uses `src` with the brand's official SVG.
- `FieldDescription icon`: a decorative glyph before the hint, sized to 14px and centred on its first line, for the settings hint style (`icon={<Icon name="info" />}`). Links in it are styled like links in a plain hint: underlined at rest, and `primary-ink` on hover.
- `FieldCount`: the settings counter at the end of a label row, "52 / 60" in 12/16px (`text-xs`) tabular figures. It is muted, and turns to the warning tone past `limit` (`data-over`) without cutting anything off. Point the control's `aria-describedby` at its `id` (one is generated if you don't pass it), so screen readers hear "52 / 60 characters" with the field (`unitLabel` sets the word) instead of after every key press. Going past `limit` is announced once, "Over the 60 character limit" (`overLimitLabel` sets the words).
- `SwitchField variant="row"`: the settings toggle row for a flush card, divided from its neighbours by the list it sits in (`divide-y divide-border`). It is padded (`px-5 py-4`, 24px sides from `sm`), uses 14px type, shows an "Enabled" or "Disabled" label before the switch, and the whole row toggles it. On both variants, `stateLabel` turns that label on or off (`{ on, off }` sets the words; screen readers skip it, since the switch announces its state), `badge` goes after the title, and `children` show under the row while the switch is on.
- `RadioCardGroup variant="rows"`: full-width option rows divided by hairlines, each with the control, a semibold title, the `badge` and a secondary description, a tint on the selected row and a hover tint. `RadioCard details` holds the chosen option's own fields outside the radio: under its row, or, in the default `cards` variant, under its card across the group's columns. Arrow keys still move and select. The control is `RadioGroupItem`'s radio: an 8px dot, and a solid disc when checked in dark mode. A disabled row keeps its text and dims only its radio, to 50%, as `RadioGroupItem` does. In rows, an option's `className` goes on its row, so `className="opacity-60"` dims an unavailable row with its tint and details.
- `CheckboxCard` and `CheckboxCardGroup`: the same cards and rows for picking several options, with `badge`, `details` and the indeterminate state. Rows draw `Checkbox`'s box and mark, and a disabled row dims only its checkbox.
- `RadioGroupIndicator` and `CheckboxIndicator`: `RadioGroupItem`'s dot and `Checkbox`'s check or dash, for drawing the same mark inside a custom radio or checkbox. `RadioGroupItem` and `Checkbox` render them and look the same.
- `PasswordInput savedSuffix`: marks a secret that is already saved. The empty field shows the last characters after a mask (`••••••••4f2a`), and screen readers hear "Saved, ends in 4f2a. Leave blank to keep it."; `savedPlaceholder` and `savedLabel` set the words. The field then defaults to `autoComplete="new-password"` and carries `data-1p-ignore` and `data-lpignore="true"`, so a browser or password manager doesn't fill a login password into it and replace the secret on save; pass `autoComplete` to choose your own. The show/hide button appears once something is typed, since an empty field has nothing to reveal.
- `Textarea softLimit`: the count measures against a soft limit and turns to the warning tone past it, without cutting the text off. Screen readers hear once that the text went past it, "Over the 160 character limit" (`overLimitLabel` sets the words). `Input` takes the same `showCount`, `softLimit`, `countLabel` and `overLimitLabel`.
- `Sidebar` `theme="light"`: the light rail of the redesigned dashboard (white rail, grey hover, brand-blue current item) on the desktop rail, a `collapsible="none"` panel and the mobile sheet. Without the prop, a sidebar follows `data-sidebar-theme="light"` on an ancestor (on `<html>`, the mobile sheet's portal follows too), and `theme="dark"` keeps one dark there. The light colours are set on the sidebar itself, so tooltips, menus and toasts opened from it keep their own.
- `SidebarProvider` `shortcutKey`: the key that toggles the sidebar with Cmd or Ctrl (default `"b"`), or `false` to turn the shortcut off, e.g. for a second provider on the page.
- Rail tokens from the dashboard design, with `bg-`/`text-` utilities: `--sidebar-primary-ink` (brand blue as text on the rail), `--sidebar-elevate` (a raised tile or button), `--sidebar-strong` (emphasised text), `--sidebar-alt` and `--sidebar-tabs` (the selected segment and track of a switch on the rail).
- `--tooltip` and `--tooltip-foreground` (`bg-tooltip`, `text-tooltip-foreground`): the surface and text of tooltips and toasts, `#09090b` and `#ffffff` in both themes. They are separate from the rail, so a light or restyled rail leaves tooltips and toasts alone, and from `--inverse`, which stays the save bar's.
- `Text`: the P3 type scale as a component. `variant` picks one of 13 sizes (`display`, `h1`–`h6`, `body-l`, `body-m`, `body-s`, `caption-l`, `caption-m`, `caption-s`; default `body-s`, 16/24, as in the Settings prototype), `weight` one of 7 (`light`, `regular`, `medium`, `semibold`, `bold`, `extrabold`, `black`; default `regular`) and `tone` a token colour (`default`, `secondary`, `muted`, `brand`, `success`, `danger`, or `inherit` for none; default `default`); `numeric` sets tabular figures. The headings render `h1`–`h6`, `display` and the body sizes a `p`, and captions a `span`. `as` changes the element, and `Text` then takes that element's props, so `<Text as="label" htmlFor>`, `<Text as="a" href>` and `<Text as="time" dateTime>` type-check. `TEXT_VARIANTS`, `TEXT_WEIGHTS` and `textVariants` are exported too, for pickers and for giving another element the same look.
- `type-display`, `type-h1` to `type-h6`, `type-body-l`, `type-body-m`, `type-body-s`, `type-caption-l`, `type-caption-m` and `type-caption-s`: the 13 P3 sizes as utilities for plain markup, from 96/100 down to 10/14, each setting font size, line height and letter spacing only. The existing `type-*` utilities and every component's own type are unchanged.
- `ActivityFeed`: a record's history in a card, built on `Timeline` and titled by a heading that names the list (`headingLevel`, default 2), for order, customer or vendor activity. Pass `entries` (title, time, `dateTime`, description, tone, icon, `note`) in the order to show them; notes sit in their own shaded box with line breaks kept. `onAddNote` adds a note box that uses `Textarea softLimit` for its count (`noteMaxLength`, default 500; going over is announced once), with empty and too-long errors and a busy state. It clears when the promise resolves, unless more was typed meanwhile; when it rejects, the text stays and `labels.addNoteError` is shown. `disabled` turns the box off, and every string is in `labels`.
- `Timeline`: events in order, each marked by a dot on a line that joins it to the next, for cart and order histories and activity logs. `TimelineItem` takes a `tone` (`default`, `primary`, `success`, `warning`, `destructive`), `upcoming` for a step still to come (a dashed hollow marker, quieter text, and `upcomingLabel`, default "Upcoming", read to screen readers) and an optional `icon` in place of the dot (once any item has one, every marker takes its width, so a mix of dots and icons keeps the line straight); `TimelineHeader` puts `TimelineTitle` and `TimelineTime` (a `<time>` element when given `dateTime`) on one row; long titles and descriptions wrap, with `TimelineDescription` below. It renders an ordered list, keeps the marker out of the accessibility tree, and mirrors itself in RTL.
- `IconProvider glyphs={…}`: swaps the glyph that every `Icon` below it draws for the names given, including the icons inside library parts such as `SettingsNav`. A nested provider stacks on the outer one. A glyph the provider swaps in keeps its own stroke width unless the `Icon` passes `strokeWidth`. A server component can't pass components to a client one, so in Next.js build the `glyphs` map in a `"use client"` file. Without a provider, every name draws the same glyph as before.
- `P3IconProvider`: every `Icon` below it draws the FlyCommerce P3 Figma icon set. It takes no props, so a server component such as a Next.js layout can render it. It has its own module, so `Icon` and `IconProvider` don't carry the P3 glyphs (about 15 KB gzipped). An `IconProvider` inside it lays its `glyphs` over the set.
- `P3_GLYPHS`: the FlyCommerce P3 Figma icon set that `P3IconProvider` draws, as a `glyphs` map. It lists the 75 names whose P3 glyph differs from the default: 43 take a Feather glyph instead of a Lucide, Tabler or Phosphor one, or another Feather glyph (`categories`, `pending`, `password`, `abandonedCart`, `setupGuide`, `support`…), and 32 take one of 23 FlyCommerce glyphs from the P3 file (`products`, `vendors`, `payouts`, `bank`, `storefront`…). Each FlyCommerce glyph is one 24×24 SVG with 2-decimal paths, drawn at its Figma stroke width: 0.59 for `collections`, 0.8 for `bank`, 0.97 for `customers`, 1.78 for `delivery` and 1.8 for `products`.
- `Icon` names `play`, `sidebarToggle`, `list`, `todo` and `reports`.

### Changed

- `SelectContent` opens the list 6px below the field, aligned to its start and at least as wide as it, instead of over the field with the chosen row on the value: `position` now defaults to `"popper"`, `align` to `"start"` and `sideOffset` to `2` (the list's own 4px slide makes 6px). The list has 4px inner padding and grows with its items up to 18rem, or the space left if that is less, then scrolls. Pass `position="item-aligned"` for the old placement. Lists that already pass `position="popper"` now start-align, sit 2px further away and stop at 18rem; pass `align="center"` and `sideOffset={0}` to keep their old position.
- `Select` rows are at least 36px tall and 1px apart, and the chosen row is medium weight. While the list is open, the trigger's border is brand blue and its chevron turns up. In the trigger, an icon or flag sits 8px from the value (was 6px), and the chevron sits 8px from it, including in `RichTextEditor`'s block select (was 4px).
- Highlighted menu rows take a soft brand tint with the popover's text colour instead of grey: hover, keyboard focus and open submenus in `DropdownMenu`, `ContextMenu` and `Menubar`, and highlighted rows in `Select`, `Combobox` and `Command`. Check marks are brand blue (`--primary-ink`) in all of them, chosen `Combobox` rows are medium weight like `Select`'s, and destructive items keep their red. The tint is `--primary-subtle` (in dark mode with 30% `--primary` mixed in) unless the `--accent` token, which only menu rows use, is set. To keep grey rows, set `--accent: #f1f1f3` in your theme.

The editor takes typing straight away; closing tags and indentation follow the language once its pack has loaded, a moment later. Plain text (`"text"`, the default) loads none. - **Right-to-left** layout support and translatable labels on every component.
- **Claude Code plugin** (`flycommerce-ui`) that teaches Claude the components, tokens, icons and migration map.
