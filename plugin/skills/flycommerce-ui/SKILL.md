# Building FlyCommerce UI with @flycommerce/ui

`@flycommerce/ui` is the single source of FlyCommerce's look: shadcn/Radix components restyled to the dashboard redesign (the P3 Figma tokens), with the PM prototype filling gaps. Screens compose it; they never restyle it.

Live gallery (every component, variant and state, light/dark/RTL/mobile): https://ui.flycommerce.com (or `pnpm dev` in the flycommerce-ui repo). Every section has a **Code** tab with a copy-paste example generated from the demo itself (imports already point at `@flycommerce/ui`); start from it instead of writing a screen from scratch.

Generated references in this skill (always current, read them instead of guessing):

- `references/exports.md`: every export and which module it comes from
- `references/icons.md`: every `<Icon name>` value
- `references/tokens.md`: every design token and its Tailwind utility
- `references/migration.md`: dokan-ui / Headless UI / react-select → @flycommerce/ui mapping
- `references/dashboard-design.md`: the redesigned dashboard's look (surfaces, shadows, radii, icons, icon chips, tables, badges) and the library equivalent of each pattern. Read it before building or migrating any `/admin` screen.

## Setup (once per app)

```bash
pnpm add @flycommerce/ui sonner
```

Tailwind v4 apps, in the main CSS file:

```css
@import "tailwindcss";
@import "@flycommerce/ui/tailwind.css";
@import "@flycommerce/ui/fonts.css"; /* Inter, if the app doesn't load it already */
```

An existing app adopting the library page by page imports `@flycommerce/ui/tailwind-core.css` instead of `tailwind.css`: the same minus the global base layer (`body` background and text colour, border and outline colours on every element, Inter on `html`), so unmigrated pages keep their look.

Apps without Tailwind: `import "@flycommerce/ui/styles.css"`.

At the app root: wrap in `<TooltipProvider>` (and `<DirectionProvider dir>` for RTL locales), render one `<Toaster />`, and set `data-theme="dark"` (or the `dark` class) on `<html>` for dark mode.

## Hard rules

1. **Import from `@flycommerce/ui` only.** Not `@getdokan/dokan-ui`, not Headless UI, not raw Radix, not `react-select`, not `react-icons`/`lucide-react` directly. The one exception is a brand's own logo from `react-icons/si` inside `BrandMark`: `react-icons` is this library's dependency, not the app's, so add it to the app's own `package.json` first (pnpm's strict mode won't resolve it otherwise), and pass the brand's colours to `BrandMark`'s `color` and `background` props, never through classes or `style`. Otherwise, prefer `src` with the brand's official SVG. If the library lacks something, add it to the library (with a gallery demo) instead of building a one-off in the app.
2. **No raw colours or arbitrary values in screens.** No `#hex`, `rgb()`, `bg-[#…]`, `text-gray-500`, `border-gray-200`. Use tokens: `bg-page` (app canvas), `bg-card`/`bg-background` (surfaces), `text-foreground`, `text-foreground-secondary`, `text-muted-foreground`, `border-border`, `border-border-subtle`, `bg-muted`, `bg-primary` (blue fills), `text-primary-ink` (blue text and links; `text-primary` is too dark in dark mode), `text-destructive`, `text-success-strong`, `text-warning-strong`, `shadow-1`, `shadow-card` (cards), `rounded-control` (8px controls), `rounded-xl` (12px cards). See `references/tokens.md`.
3. **Don't restyle components with `className`.** `className` is for layout (width, margin, grid placement). A different look is a `variant` or `size`; if none fits, the variant belongs in the library.
4. **Icons go through `<Icon name="…" />`** using a meaning from `references/icons.md` (e.g. `orders`, `vendors`, `payouts`). Inside `Button`, place the icon as the first child; it sizes itself. An app on the P3 Figma icon set wraps its tree once in `<P3IconProvider>`; screens keep the same names and never swap a glyph with a `react-icons` import. In RTL the directional names (`back`, `forward`, `prev`, `next`, `redirects`, `impersonate`, `signOut`, `sidebarToggle`, `list`) mirror by themselves: don't flip them (`rtl:rotate-180` or a flipping wrapper turns them back, `rtl:-scale-x-100` is redundant); `mirror={false}` keeps one as drawn.
5. **Every user-visible string is translatable.** Components expose label props (`labels`, `confirmLabel`, `placeholder`, `clearLabel`, `closeLabel`…); pass the app's `t()` output. Never leave the English defaults in a localized screen. See **Translating labels** below.
6. **Keep accessibility intact.** Icon-only buttons need `aria-label`. Inputs need a `FieldLabel htmlFor`. Don't remove focus rings: they only show for keyboard users.
7. **Mobile first.** Every screen must work at 375px: no horizontal page scroll, toolbars wrap, tables scroll inside their card (DataTable does this).

## Translating labels

Every built-in string has an English default you replace with `t()` output:

- One string is one prop: `closeLabel` (`DialogContent`, `SheetContent`, `CommandDialog`, `DialogFooter`), `label` (`SidebarTrigger`, `CarouselPrevious`, `CarouselNext`, `PaginationEllipsis`, `BreadcrumbEllipsis`), `placeholder`, `clearLabel`, `presetsLabel`.
- Several strings are a `labels` object (`DataTable`, `MediaPickerDialog` with nested `queue`, `grid`, `details` and `video`, `ImageUploadField`, `Sidebar` for its mobile sheet…). Text with a value in it is a function, so the translation decides the word order: `showing: (from, to, total) => t("Showing {{from}} to {{to}} of {{total}}", { from, to, total })`. Don't join translated pieces yourself.
- `locale` formats numbers and file sizes through `Intl` (`ImageUploadField`, `UploadQueue`, `MediaPickerDialog`, `MediaDetailsPanel`: pass the app's language, e.g. `"tr"`). `DatePicker`, `DateRangePicker`, `TableFilters` and `ActiveFilters` take a date-fns locale object instead (`import { tr } from "date-fns/locale"`); one from `react-day-picker/locale` also translates the calendar's buttons, after adding `react-day-picker` to the app's `package.json`.
- Parts whose only text is an accessible name take the attribute itself: `aria-label` on `Spinner`, `Pagination`, `PaginationPrevious` and `PaginationNext` (with `text` for the visible word) and `Breadcrumb`; `aria-label` and `title` on `SidebarRail`; `aria-roledescription` on `Carousel` and `CarouselItem`. `Toaster` takes sonner's `containerAriaLabel` and `toastOptions={{ closeButtonAriaLabel }}`.

## Typography

Inter throughout. Use the `type-*` utilities for size, weight and spacing and pair them with a colour utility; don't hand-pick `text-[13px] font-semibold`:

`type-page-title` (24/700) · `type-overview-value` (24/600) · `type-kpi-value` (18/700) · `type-stat-value` (24/600) · `type-stat-value-sm` (16/600) · `type-card-title` (16/700) · `type-section-label` (14/600) · `type-body` (14/400) · `type-row-title` (14/600) · `type-field-label` (14/500) · `type-kpi-label` (12/400) · `type-hint` (11.5/400) · `type-badge` (11.5/600) · `type-table-header` (12/600 uppercase) · `type-group-heading` (10.5/650 uppercase).

Components already apply these internally (`PageHeaderTitle`, `CardTitle`, `FieldLabel`, table headers…); reach for the utilities only in custom layout.

**The P3 type scale** is the Settings redesign's type, as `<Text variant weight tone numeric>` or as the `type-display` … `type-caption-s` utilities (size, line height and letter spacing only): `display` 96/100 · `h1` 64/72 · `h2` 56/64 · `h3` 48/56 · `h4` 40/48 · `h5` 32/40 · `h6` 24/32 · `body-l` 20/28 · `body-m` 18/26 · `body-s` 16/24 · `caption-l` 14/20 · `caption-m` 12/16 · `caption-s` 10/14. `Text` defaults to `body-s` (16/24), `weight="regular"` and `tone="default"`, as the Settings prototype's `Text` does; most body copy there passes `variant="caption-l"` (14/20). Weights run from `light` to `black`, and the tones are `default`, `secondary`, `muted`, `brand`, `success`, `danger` and `inherit`. `h1`–`h6` render headings, `display` and the body sizes `p`, captions `span`. `as` changes the element and takes that element's props (`<Text as="label" htmlFor>`, `<Text as="a" href>`, `<Text as="time" dateTime>`); pass `as="span"` for body text inside a `<p>`, `<label>` or button. Numbers take `numeric`.

**Which scale.** Use `Text`, or the P3 utilities in plain markup, in the Settings redesign and on new screens. Keep the `type-*` utilities above on current dashboard pages, so each page stays on one scale. Where the two scales meet:

- `type-h6` and `type-page-title`: both 24/32. `type-page-title` also sets bold (700) and no letter spacing; `type-h6` sets -0.3px and leaves the weight to `Text` (regular unless set).
- `type-caption-l` and `type-body`: both 14px with no letter spacing. `type-body` also sets weight 400 and a 1.5 line height (21px); `type-caption-l` sets 20px and leaves the weight to `Text`.
- `type-caption-m` and `type-kpi-label`: both 12/16 with no letter spacing. `type-kpi-label` also sets weight 400; `type-caption-m` leaves it to `Text`.

**Size through `variant`, not `className`** (hard rule 3). `cn` doesn't treat a `type-*` utility and a `text-<size>` class as conflicting, so `<Text className="text-sm">` keeps both and the size depends on CSS order. Pick the `variant` with the size you need. `leading-*`, `tracking-*` and `font-*` in `className` still adjust a variant.

## Pages of a FlyCommerce app

An app that merchants install shows its pages inside the dashboard, framed on the app's own origin. This skill covers how those pages look. How they're framed, how they get a session token and how they call the store belong to FlyCommerce's other plugins, from the `flycommerce` marketplace (`getdokan/flycommerce-sdk`):

- **flycommerce-apps**: installs, the app bridge, session tokens, webhooks, private and listed apps. It installs this plugin with it.
- **flycommerce-api**: calling the store's endpoints.

Use them alongside this one when they're available. If the project is an app and they aren't, ask the developer to run `/plugin marketplace add getdokan/flycommerce-sdk` and `/plugin install flycommerce-apps@flycommerce`; you can't run `/plugin` commands yourself.

## Before you finish

- Type-check and lint the app.
- Open the screen at desktop and at 375px, in light and dark, and in RTL if the app is localized: no horizontal scroll, nothing clipped, nothing unreadable.
- Grep your diff for `#[0-9a-fA-F]{3,6}`, `-\[`, `gray-`, `lucide-react`, `react-icons`, `@getdokan/dokan-ui`, `@headlessui`: each hit needs a reason or a fix.
- If you added a missing variant or composite, add it to the flycommerce-ui library with a gallery demo, and regenerate this skill's references with `pnpm skill:refs`.
